# 可靠性：超时、重试、熔断、降级到备用模型

对应页面：[可靠性：超时、重试、熔断、降级到备用模型](https://study.ainiya.de/agent/prod-reliability.html)

全景“大促夜里 1000 个告警同时涌进来”第 ⑥ 站：把 20:03 那次故障按 30 倍速重演 4 遍。

| 文件 | 做什么 |
|---|---|
| `fake_provider.py` | 会出故障的假供应商：`main` 在 20:03～20:06:20 有 70% 回 529、全程 3% 卡住 5 分钟；`backup` 不出故障但额度只有 15 万/分钟；`GET /stats` 按“故障前 / 故障中 / 故障后”数请求 |
| `breaker.py` | `CircuitBreaker`（按次数的滑动窗口，CLOSED / OPEN / HALF_OPEN，只数 529、5xx、超时、连接错误）和按 token 的 `TokenBucket` |
| `night.py` | A SDK 默认 / B 三层重试 / C 一层重试 + 超时 60 秒 + 熔断 + 备用 / D 再加截止时间和“P2 只分诊” |

没有真模型，也不需要 API key。

## 怎么跑

```bash
cd agent && uv sync
uv run python prod-reliability/night.py      # 约 3 分钟
uv run pytest prod-reliability/
```

## 练习

先猜结果，再运行。

1. 把主模型的令牌桶从 36 万调到 50 万（超过供应商的 40 万），再让 `provider_down()` 把 429 也算失败：没有故障的 20:00～20:03，熔断器会不会打开？

3. 去掉 backup 的令牌桶：熔断打开的 3 分钟里，备用模型吃了多少 429？
4. 给 P0 留 4 个专用 worker（舱壁）：D 里因为截止时间转人工的 P0 还在不在？
