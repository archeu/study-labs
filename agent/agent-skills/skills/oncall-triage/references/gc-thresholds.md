# GC 判断阈值（order-svc，堆 1 GB，G1）

| 看什么 | 正常 | 要关注 | 基本可以定性 |
|---|---|---|---|
| 10 分钟内 Full GC 次数 | 0 | 1 | ≥ 2 |
| 单次停顿 | < 200 ms | 200 ms～1 s | > 1 s（接口 p99 会直接被拖过 2 s） |
| Full GC 回收后堆占用 | < 50% | 50%～70% | > 70%：有对象一直被引用，回收不掉 |
| Humongous Allocation | 偶尔 | 频繁出现 | 和 Full GC 同时出现：有超过半个 region 的大对象（大数组、大 List） |

定性之后的常见根因：

- 一次把几十万行读进内存（导出、报表接口）→ 改分页或流式写出。
- 本地缓存没有上限 → 加最大条数和过期时间。
- 大对象反复创建 → 复用或拆小。
