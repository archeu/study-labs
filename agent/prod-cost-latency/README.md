# 成本和延迟：缓存、模型路由、流式、并行

对应页面：[成本和延迟：缓存、模型路由、流式、并行](https://study.ainiya.de/agent/prod-cost-latency.html)

全景“大促夜里 1000 个告警同时涌进来”第 ⑤、⑦、⑩ 站：给一次调查记一本账，一刀一刀叠上五种做法，看钱、时间、额度各省了多少，瓶颈挪到了哪。

`ledger.py` 是**计算**，不是实测：开头的常量就是全部假设（token 轨迹、单价、速度，和全景页一致），计费规则照 Claude API 的提示词缓存规则：命中的前缀按 0.1 倍、不算 ITPM；新写进缓存的按 1.25 倍、算 ITPM。页面上的实验台是同一套算法的 JS 版，逐行对过。

## 怎么跑

```bash
cd agent
uv run python prod-cost-latency/ledger.py
uv run pytest prod-cost-latency/
```

## 练习

先猜结果，再运行。

1. 让历史缓存的第一轮读不到前缀（模拟系统提示里混进了时间），第 2 行的钱和并发变了多少？
2. `TRIAGE_STOP` 从 0.4 改成 0.7：钱降多少？漏判率如果从 2% 涨到 10%，值不值？
3. `REPORT_OUT` 从 600 改成 2000：从哪一行开始瓶颈变成 OTPM、并发掉到多少？
4. 把 `plan()` 改成 12 轮：基线和“历史也缓存”的差距变大还是变小？
