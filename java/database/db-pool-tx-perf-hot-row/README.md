# 池子从 10 开到 50，付款一点没快：连接池与事务性能（下一圈）

对应页面：[池子从 10 开到 50，付款一点没快：连接池与事务性能（下一圈）](https://archeu.github.io/study-notes/database/db-pool-tx-perf-hot-row.html)

交易靶场 20:00 秒杀 88 号商品：64 个线程（模拟 Tomcat）同时付款，每笔一个事务：改自己的订单、写一条流水、扣 88 号库存（人人都改这一行），再调一次风控接口（`sleep(20)` 模拟）。`run.sh` 起一个 MySQL 8.4 容器（默认配置，双 1 开着，buffer pool 512 MB），然后跑 `PayLab`：

- `hot`：三个开关两两组合共 8 组：风控在事务里 / 挪出事务 × 库存最先改 / 最后改 × HikariCP 池子 10 / 50。每组看每秒付款、延迟（平均、中位、p99）、平均等连接多久、扣库存那条 UPDATE 多久（等锁 + 执行）、提交多久、HikariCP 门口排队峰值、InnoDB 里 `LOCK WAIT` 事务峰值、每次提交摊到几次 binlog sync。
- `size`：去掉热点行（每笔只改一行随机订单 + 写流水，不调风控），池子 1、2、4、8、16、32、64，看吞吐、延迟、每次提交摊到几次 redo fsync 和 binlog sync（组提交）。

用 JDBC 手写事务，等价于 Spring 的 `@Transactional`：借连接 → `setAutoCommit(false)` → SQL → `commit()` → 还连接。HikariCP 用 4.0.3（最后一个支持 Java 8 的版本，Spring Boot 2.7 自带），这样能 `--release 8` 编译；本页用到的行为和 Boot 3.5 的 6.3.3 一样。

## 怎么跑

需要 Docker（拉 `mysql:8.4`，约 800 MB）、JDK 8+、Maven。

```bash
cd java/database/db-pool-tx-perf-hot-row
./run.sh          # 起容器、建表，跑 hot 和 size，每组 8 秒（本机不在 docker 组里：DOCKER="sudo docker" ./run.sh）
./run.sh 15       # 每组 15 秒
./run.sh clean    # 删容器和数据卷
```

MySQL 在 127.0.0.1:33093，root / root。也可以在 IDE 里直接运行 `PayLab`，参数 `setup` / `hot 8` / `size 8`（先 setup 一次）。

## 练习

先猜结果，再运行。

1. **库存分桶**：把 88 号的库存拆成 8 行（加一列 `bucket` 0～7），每笔随机扣一行，跑第 7 组的配置。吞吐是 300 的 8 倍吗？binlog sync / 提交还是 1.00 吗？
2. **给等待设上限**：第 2 组的配置，事务开始前 `SET SESSION innodb_lock_wait_timeout = 1`，`hc.setConnectionTimeout(1000)`。吞吐变吗？会有多少笔报错，报的是哪两种错？
3. **拿持久性换速度（只在靶场上试）**：第 7 组的配置，先 `SET GLOBAL innodb_flush_log_at_trx_commit = 2; SET GLOBAL sync_binlog = 0;`。吞吐变成多少？瓶颈换成了谁？
