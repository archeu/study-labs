# 满减叠加券：技术方案（v1 草稿，周四早上的样子）

作者：小林　状态：草稿

## 1 背景和问题

运营要在 12.12 上线“满 300 减 40”，并且能和券叠加。

## 2 目标和非目标

### 目标

- 支持满减和券叠加。

### 非目标

无。

## 3 现状

算价写在 order-svc 的 OrderService.calcPrice() 里。

## 4 方案

- 算价放进 coupon-svc 的独立模块，order-svc 把验券调用换成“算价加锁券”。
- 下单时把每行分摊写进 order_line 的 3 个新列，退款读这 3 列。
- 每种优惠一个 DiscountRule 实现类，按顺序依次执行。

## 5 放弃的方案

- 规则引擎，不合适。
- 新建 pricing-svc，太重。

## 6 风险和降级

| 风险 | 触发 | 处理 |
|---|---|---|
| 算价接口超时 | 超过 300 ms | 降级为按原价下单 |

12.11 全量发布，观察一天。
