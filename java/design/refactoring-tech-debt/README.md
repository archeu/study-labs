# 先让改动变容易，再做那个容易的改动：重构与偿还技术债

对应页面：[先让改动变容易，再做那个容易的改动：重构与偿还技术债](https://study.ainiya.de/design/refactoring-tech-debt.html)

一段没有测试的老算价代码，先钉住、再搬、再双跑，最后才加满减。

| 类 | 是什么 |
|---|---|
| `Legacy` | 老代码，当黑盒：三种券，折扣券向下取整（多年的老毛病，财务对账一直按它算） |
| `Moved` | 搬成规则对象的两个版本：`AS_IS` 原样搬；`WITH_ROUNDING_FIX` 搬的时候顺手改成了四舍五入。`payWithPromotion` 是藏在开关后面的满减 |
| `RefactorWalkthrough` | main：记下 108 组老代码的输出当标准答案，拿两个版本各比一遍；一万笔固定种子的模拟订单双跑；打开开关再比 |

## 怎么跑

- IDE：打开仓库的 `java/pom.xml`，运行 `labs.design.refactoring_tech_debt.RefactorWalkthrough` 的 main。
- 命令行：`cd java && mvn -q -pl design/refactoring-tech-debt compile exec:java -Dexec.mainClass=labs.design.refactoring_tech_debt.RefactorWalkthrough`

## 预期输出

2 核 ARM 虚拟机，OpenJDK 17.0.21，2026-11-16（随机种子固定，每次一样）：

```
== 1. 钉住：拿老代码的输出当标准答案（特征测试）
记下 108 组输入和老代码的输出。不管这些输出“对不对”，现在线上就是这样

== 2. 搬的时候顺手把折扣券的舍入“修”了
108 组里有 10 组和老代码不一样，前几组：
  99.90 元，9.5 折：老代码 94.90，新代码 94.91
  99.90 元，8.5 折：老代码 84.91，新代码 84.92
  0.01 元，9.5 折：老代码 0.00，新代码 0.01

== 3. 原样搬，连老毛病一起搬
108 组里有 0 组和老代码不一样，可以往下走

== 4. 双跑：一万笔模拟的线上订单，新旧两边都算，只用旧的结果
修了舍入的版本：10000 笔里 1298 笔不一样，合计差 12.98 元
原样搬的版本：10000 笔里 0 笔不一样

== 5. 加功能：打开满减的开关，再比一次
原样搬 + 满减开关打开：10000 笔里 1512 笔不一样，合计差 57235.00 元；其中 1512 笔是够门槛的满减订单（一共 1512 笔），别的订单差异 0 笔
```

## 练习

先猜结果，再运行。

1. 在 `Moved` 里把现金券改成“最多减到 1 分钱”。108 组里会红几组？红的是哪几组？
2. 特征测试的输入里没有 0 元和负数。加进去，看 `Legacy` 吐出什么，再把它钉住。
3. 正式修那个舍入：加一个开关 `roundingFix`，在双跑里验证差异只落在折扣券订单上；写一段变更说明给财务。
