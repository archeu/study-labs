# ADR-0009 每行分摊在下单时存进订单，退款按快照算，不重算

- 状态：已接受
- 日期：2026-12-04
- 参与：小林（提出）、老陈、订单组、财务

## 背景

规则 R4：退一件，退这一行的实付。这要知道下单时每一行便宜了多少。
现在 orders 表只有整单优惠一个数。活动会结束，规则会改：12.13 活动可能从满 300 减 40 改成满 400 减 50。

## 决定

我们在下单时把每一行的分摊金额、活动 id、券 id 写进 order_line（discount_share、promotion_id、coupon_id），之后不再修改。退款只读这份快照，不调营销。

## 放弃的方案

- 退款时调营销重算。输在：活动结束或规则改过以后，算不回当时的数（用户 1024 那单，改规则后重算是 101.59，应退 104.49）；营销不可用时退款也做不了。
- 只存整单优惠，退款时按原价比例现算。输在：尾差归哪一行没有记录，多次部分退款加起来可能和整单对不上。

## 后果

- 好的：退款金额永远和当初付的对得上；退款不依赖营销是否可用。
- 坏的：order_line 多 3 列；老订单没有快照，上线前要按老算法回填一次。

## 重新看的条件

- 出现“下单以后还能改价”的业务（比如客服改价），快照就不再是只写一次，需要版本。
